# BudgetBite — Proof of Concept

BudgetBite is a web app that gives you a cheap recipe for your budget and
dietary goal, with a cost per serving and macros that are actually calculated
instead of guessed. This repo is the proof of concept for my CIS 3296 project.

## What the PoC does

You pick a budget per serving and a dietary goal, and the app sends them to an
API route (`/api/recipe`) that returns a recipe with:

- **Cost per serving**, calculated from ingredient prices. Each ingredient is
  converted to grams, and its cost is `grams used × (package price ÷ package grams)`.
  The total is divided by the number of servings. See `lib/cost.js`.
- **Budget check.** The app tells you if the recipe fits your budget, and if it
  doesn't, how much over it is.
- **Upfront shopping cost**, which is what you'd actually pay at the register
  for the full packages.
- **Macros per serving** (calories, protein, carbs, fat), calculated from
  **USDA FoodData Central** nutrition data. See `lib/nutrition.js`.

### What's real and what's still mocked

| Part | Status in the PoC | Full project |
|---|---|---|
| Nutrition data | Real USDA FoodData Central API call (falls back to stored values if the call fails) | Same |
| Cost math and budget check | Real | Same |
| Ingredient prices | Hardcoded sample table in `lib/prices.js` | Kroger API near the user's ZIP code, otherwise regional averages from BLS/USDA ERS data |
| Recipe | Hardcoded (the same recipe comes back for every diet) | Generated by the OpenAI API as structured JSON |
| Over budget | Flagged with the overage amount | Swaps in cheaper ingredients, then asks the model for a revised recipe |

The comments in `app/api/recipe/route.js` show where the OpenAI call goes.

The ingredients table on the page shows where each nutrition number came from
("USDA" or "offline"), and hovering over it shows which USDA food it matched.

## How to compile and run

```bash
npm install
npm run build   # compiles the app
npm run start   # runs the compiled app at http://localhost:3000
```

For local development with hot-reload instead:

```bash
npm install
npm run dev      # runs at http://localhost:3000
```

Open http://localhost:3000, pick a budget and dietary goal, and click
"Get a recipe".

### API key (optional)

The app works without any setup. It uses USDA's public `DEMO_KEY`, which has a
low rate limit. To use your own free key:

1. Get a key at https://fdc.nal.usda.gov/api-key-signup
2. Copy `.env.example` to `.env.local`
3. Put your key after `USDA_API_KEY=`
4. Restart the server

If the USDA call fails (no internet, rate limit, bad key), the app still works
and uses stored approximate values, and the table shows "offline" for those
ingredients.

## Tests

```bash
npm test
```

This runs the unit tests in `test/` with Node's built-in test runner. They
check the unit conversion, the cost-per-serving math (including the rice
example from my proposal: 185 g from a $1.79, 907 g bag is about $0.37), the
budget check, and the upfront cost.
